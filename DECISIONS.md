# Decisions

## Design decisions

- **FastAPI + SQLAlchemy + SQLite:** FastAPI provides a small typed API, SQLAlchemy provides the ORM/session boundary, and the supplied SQLite database remains the source of truth. The existing schema is mapped without replacing or reseeding the provided data.
- **Backend structure:** HTTP routers, Pydantic request/response schemas, SQLAlchemy models, and service-layer query/business logic are separated so each concern is easy to test and maintain.
- **Inventory filters:** The table supports free-text search across item, category, and supplier, exact category and supplier filters, and stock states: in stock (50+), low stock (1-49), and out of stock (0). Pagination shows 12 items per page so the table remains easy to scan.
- **Quantity updates:** Quantity editing uses direct numeric entry plus adjacent `-` and `+` controls. Changes require an explicit Save action, preventing accidental updates from blur events. Negative quantities are rejected by the update API.
- **Bulk pricing:** Selected rows can receive either a percentage adjustment or a fixed-dollar adjustment. The action bar states the number of selected items and displays the correct `%` or `$` unit. The API rejects negative resulting prices and refuses to reprice records without a price.
- **Dashboard:** The dashboard focuses on metrics available in the source data: inventory value, units on hand, SKU count, low-stock count, out-of-stock count, data-quality issues, unpriced SKUs, category value, supplier value exposure, and an attention queue. Sales, turnover, and historical trend charts were intentionally not invented because the database has no sales, cost, or timestamp fields.
- **Data quality:** Literal `Null` item names are displayed as `Unnamed item`; negative quantities are displayed as `Invalid stock` and `Data issue`. The source database is not silently modified.
- **Connectivity:** The browser stores the latest successful inventory and dashboard responses in `localStorage`. If the API is unavailable, the last view remains readable and edits are disabled until the connection returns.
- **Configuration:** The frontend defaults to `http://localhost:8000/api` and supports `VITE_API_URL` through `frontend/.env.local` for another backend host or port.
- **Simple AI architecture:** TypeSafe Jev routes to exactly one of four Mistral agents: Text-to-SQL, PDF RAG, single/bulk quantity updates, or absolute price setting. Low-confidence and unsupported requests ask for clarification. There is no tool loop or Groq integration. Historical audit questions route to documents; current inventory facts route to SQL. Separate typed quantity and price actions keep mixed-field requests unsupported.
- **Matched routing comparison:** An opt-in Mistral shadow classifier observes exactly Jev's input and five route definitions; Jev remains the sole execution authority, with no fallback. A separately selected fixed 20-case/40-call benchmark alternates classifier order, uses one attempt each, and never executes inventory actions. Both modes share the chat gate, persist local results, and appear inline on the trace page in place of cross-task agent averages. Latencies and token means use matched successful/reporting subsets, unknown usage stays unknown, and agreement is not accuracy. Background jobs save each pair and are marked interrupted on restart with no automatic paid retries.
- **Text-to-SQL:** SQLGlot validates inventory-only SELECT queries; an independent read-only SQLite connection, authorizer, and resource limits enforce execution boundaries. Exact SQL/results are retained in the separate trace dashboard. The drawer streams an additional Mistral explanation using a bounded result sample; this can still be mistaken and is not the source of truth.
- **PDF knowledge/RAG:** pypdf extracts page-aware overlapping chunks from the three fictional knowledge PDFs. Mistral creates 1,024-dimensional embeddings; Qdrant Cloud stores vectors and text. Explicit ingestion stages a versioned collection and atomically switches an application-owned alias only after confirmed writes. The fingerprint includes corpus bytes, model and chunking version. Stale corpus queries fail rather than serve outdated text; unchanged ingestion is idempotent. No automatic collection deletion or background paid ingestion is performed.
- **RAG grounding:** The FAQ route retrieves up to six passages above a documented cosine cutoff, validates payload provenance against local PDFs, and generates claims referencing server-numbered source/excerpt IDs. The server resolves IDs to verbatim evidence quotes, avoiding fragile model-copied quotations. Unknown references fail explicitly; empty or insufficient retrieval refuses an answer without dummy fallback. Provenance checks cannot prove semantic correctness. The streamed explanation must preserve citation labels; PDF/page references are displayed separately from generated text and full evidence stays in local Traceability.
- **Instant starter questions:** The frontend randomly selects three prompts (one per original SQL/PDF/quantity starter scope) from 30 curated project-specific examples, each at most ten words. Selection happens once per page load with no LLM or API request, cost, loading state, or trace. Starters disappear after the first submission and do not return on reopening or New chat; no refresh button or follow-up list. Selection only fills the composer and never executes stock changes. Example IDs must be verified. The obsolete paid-generation endpoint and schemas are removed. The input clears immediately on Send while the submitted request is retained for processing/audit. The compact launcher has a gradient-highlighted border.
- **Human approval:** AI quantity/price previews require explicit IDs or an unambiguous verified session selection and absolute values, expire after ten minutes, and require approval. Snapshot checks, every batch update, and decision status share one SQLite transaction. Missing/stale items prevent partial changes; repeated approval is idempotent. Price setting supports NULL initialization or replacement, 0-1,000,000 USD with at most two decimal places, and never adjusts relative to an old value. Unpriced is displayed separately from zero; price snapshots check prices and quantity snapshots check stock. Direct editing and manual bulk pricing remain unchanged.
- **Observability:** Local MLflow and optional hosted LangSmith traces contain routing, agent names, usage, latency, retrieval counts, row counts, and approval metadata, not prompts, SQL content, credentials, PDF passages, or inventory values. PDF text intentionally goes to Qdrant/Mistral for RAG; that is not a telemetry export. LangSmith uses explicit metadata-only SDK calls, not automatic instrumentation. Export failures are logged and surfaced in trace warnings without invalidating an inventory operation. Local audit evidence drives trace-dashboard charts; missing token reports are unknown, not zero. Existing old-format audit records are preserved.
- **Assistant UI and streaming:** A compact bottom-right launcher expands into an accessible right-hand drawer with pointer/keyboard resizing and remembered width. Only the Markdown response and approval preview appear there; Traceability opens a separate page for technical evidence. SSE emits real explanation deltas after validation. Stop/disconnect preserves canonical results and pending previews without approval. The streaming worker owns its database session because FastAPI 0.115 releases dependency sessions before streaming responses.
- **Visual design:** The interface is intentionally dense and operational: clear status colors, explicit action labels, responsive controls, pagination, and a scan-friendly inventory table.

## Limitations and shortcuts

- There is no authentication, role management, or multi-warehouse model. AI runs and proposal decisions have a local audit trail, but direct inventory edits do not. The AI feature is a loopback-only showcase, not a public production deployment.
- Cached data is local to one browser and is not an offline write queue. Quantity and price edits require a live API connection.
- The database is updated directly through SQLite transactions. A production multi-process deployment would need a database strategy designed for concurrent writes and migrations.
- The dashboard is a current-state report only. Historical trends would require inventory snapshots or timestamped events that are not present in the source database.
- The supplied database contains a small number of invalid or incomplete records, including negative stock and missing prices. The UI labels these clearly, but does not alter the source data.
- Automated API and browser test coverage is limited to smoke checks and build validation due to the interview time constraint.
- **Short-term memory:** A page-local parent-run reference links requests to server-stored audit turns, never a process-global last conversation. Refresh or New chat drops the reference; audit records and pending approvals remain. Context is bounded to six turns/16,000 history characters and treated as untrusted data, not current inventory. Only direct product IDs from validated SQL or quantity/price previews establish implicit update targets. Singular references require one item, "both" requires exactly two, and plural references such as "these products" require a complete verified group (2-25). Ambiguous or unverified targets require clarification; generated plans must match the entire referenced selection. Explicit IDs override memory. FAQ follow-ups use a standalone search-question rewrite and fresh retrieval/citations. No long-term user profile or memory vector store.
- AI workflow tests use mocked providers and temporary databases; live integrations require fresh keys and non-sensitive demo data. There is no durable background-job queue or cross-worker spending limiter. Read-only SQL is limited to 100 displayed rows and a bounded single-table SELECT subset. Quantity requests must supply final values and either explicit IDs or an unambiguous verified session selection; product-name guessing and relative adjustments are intentionally excluded. "Increase to" is an absolute final value, not "increase by."
- PDF retrieval uses a fixed demo cosine cutoff, not calibrated confidence or a learned reranker. OCR, access-controlled document collections, parallel ingestion coordination, obsolete-collection cleanup, and a held-out RAG evaluation suite are not included. Missing Qdrant configuration/indexing fails explicitly; existing SQL and quantity features remain available.
